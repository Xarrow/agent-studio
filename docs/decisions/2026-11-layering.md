# 分层与契约（2026-11）

这份文件回答一个问题：**出了问题该在哪一层修**。之前几次"修了没生效"都发生在跨层：
页面改对了，但传输层没压缩、部署层指错目录、资源层一次回 5MB。

```
┌─ 交付层  build / deploy ────────────────────────────────────────────┐
│  产物：web/out（静态导出）+ src/agent_studio（后端）                  │
│  单一真相：远端 start.sh 的 STUDIO_WEB_DIST 说静态目录在哪            │
│  验收：scripts/deploy-remote.sh → /api/version 比对 commit/文件数     │
├─ 传输层  HTTP ────────────────────────────────────────────────────┤
│  GZipMiddleware（text/event-stream 不压，压了流就不流）              │
│  静态资源 no-cache + ETag（chunk 名跨构建稳定，不能 immutable）        │
│  口令闸：/api/* 与静态资源都要过；/api/health、/api/version 例外      │
├─ 资源层  REST ────────────────────────────────────────────────────┤
│  列表 = 瘦身（files_count，不含正文）                                 │
│  详情 = 正文 + 附件"清单"（值为空串），要正文用 ?with_files=1        │
│  单附件 = GET /api/skills/{id}/file?path=…                          │
│  ETag：详情带 W/"<id>-<updated_at>-<with_files>"，命中 304            │
├─ 一致性层  写操作 ──────────────────────────────────────────────────┤
│  PUT /api/agents/{id} 接受 If-Match:<version>；不匹配 409             │
│  不带就不校验（CLI/脚本兼容），页面一律带                               │
├─ 聚合边界  删除 ────────────────────────────────────────────────────┤
│  删技能 = 删记录 + 删 agent_skill + 清 agent.definition.skills[].ref  │
│  别人的引用不能误删（只摘指向这个 id 的那一条）                        │
├─ 实时层  push ─────────────────────────────────────────────────────┤
│  会话级 SSE /api/sessions/{id}/stream；服务端 2s 轮询本地库            │
│  断线由浏览器重连；连续失败 3 次页面降级为 8s digest 轮询              │
│  进程内实现：多 worker 需换 Redis pub/sub（未做，已在口径里写明）      │
└──────────────────────────────────────────────────────────────────┘
```

## 为什么这样切

- **交付层单独成层**：东京没有 git、目录由 start.sh 决定，是最容易"改错地方"的一层，
  所以给它一个只做一件事的脚本 + 一个能自证的 `/api/version`。
- **压缩放传输层**：任何新接口都自动受益，不用每个 handler 记得压缩。
- **瘦身放资源层**：列表/详情/单附件三种粒度，前端按需取；正文永远不跟着列表走。
- **并发放一致性层**：`version` 是助手这条聚合根自带的，写接口用它做乐观锁，
  比加锁简单，也不会把"两个标签页"变成谁先谁后的问题。
- **级联放聚合边界**：技能被助手引用是跨聚合的引用（ref），删除时必须显式清理，
  不能指望数据库外键（引用是 JSON 里的字符串，FK 看不到）。

## 已知边界（不在这轮范围内）

1. SSE 是进程内实现；多 worker 部署要换 Redis pub/sub。
2. 技能详情仍会回 SKILL.md 正文（几十 KB）；真要更小得再拆一层"仅元数据"。
3. 压缩只做 gzip；br 需要网关层或额外中间件。
