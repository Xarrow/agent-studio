# 决策：`@` 是技能名，`#` 是版本

## 背景
社区里 `owner/repo@v1.2.3` 和 `owner/repo@skill-name` 两种写法都出现过；历史代码
（skills_repo.parse_repo_ref）把 `@` 当版本，与本规范冲突。

## 决策
- `#` 后面一律是 ref（分支/标签/SHA）；
- `@` 后面一律是技能名；解析结果里附一条 ambiguity 说明（"若是分支/标签，用 # 明确"）；
- 发现阶段如果 `@x` 找不到同名技能，不做"再当版本试一次"的隐式回退 —— 报错并提示用 `#`。

## 后果
旧写法 `owner/repo@v1.2.0` 会被当成技能名而失败；这是**故意的**：隐式二义会让错误更难查。
界面的输入框会把解析结果显示出来，用户能立刻看到 `@` 被当成了技能名。
