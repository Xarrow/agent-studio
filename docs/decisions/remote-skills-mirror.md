# 决策：镜像只用于"取内容"，提交 ID 以原始主机为准

## 背景
受限网络下需要镜像（企业内网、区域加速）。镜像运营方可以看到内容，也可能篡改。

## 决策
1. 镜像地址**只能由用户配置**，代码里不内置任何公共镜像；
2. 解析 ref 时优先向原始主机取提交 ID（git ls-remote 或平台 API）；原始主机不可达才用镜像，
   并记录 `integrity: mirror-unverified`，界面提示"内容来自镜像，未经原始主机核验"；
3. 镜像模板支持 `{url}` 占位（替换成原始地址）或完整 URL；两者都不是就当基础前缀；
4. 配置镜像时显示提示：镜像方可看到并可篡改内容。

## 后果
纯内网环境（原始主机完全不可达）仍能安装，但每次都会带 `mirror-unverified` 标注 ——
这是刻意的：用户可以据此决定要不要信。
