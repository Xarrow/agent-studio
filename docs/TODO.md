## 一、节点联邦（Agent Studio ↔ Agent Studio）

### P0 · 已拍板未实现

1. **长任务与断流的收尾**（只读查询接口）
   现状：节点间调用只有同步 SSE，网络一断，我方既不知道远端跑完没，也不敢重试（怕跑两遍）。
   要做的：加 `GET /a2a/tasks/{request_id}`，只需状态与结果，不重跑。
   验收：人为掐断连接后，本地能查到远端那次 run 的终态。

2. **幂等贯通**
   现状：调用没有稳定的请求标识，重试就会让远端再跑一次（远端若调了发消息/写库这类工具就是事故）。
   要做的：请求带 `X-Request-Id`（本地 run_id + 序号），远端按它去重；只对"接单失败"重试，不对"执行中"重试。
   验收：同一 request_id 连发两次，远端只执行一次。

3. **撤销传播**
   现状：移除节点只是本地删，对端不知道；也没有 `/revoke` 端点。
   要做的：移除时通知对端；对端把来自该节点的助手标"授权已撤销"（灰显、调用直接拒），不重试。
   验收：A 移除 B 后，B 侧调用 A 立刻失败且提示是"已撤销"而不是超时。

4. **待接受请求的闭环**
   现状：对方推名片过来只是本地多一条 pending，对方不知道结果，也没有过期。
   要做的：接受/拒绝时回推对方一次；pending 超过 7 天自动过期。
   验收：接受后对方页面上的节点状态从"待接受"变"正常"。

5. **权限范围（同步问答 / 长任务 / 文件回传）**
   现状：只做了整助手开关，没有细粒度；A2A 入口也没有对 message 结构做校验。
   要做的：先做两条**真限制**（是否允许带附件、是否允许超 N 分钟的轮次），其余只做卡片里的提示语。
   验收：关掉"允许附件"后，带附件的请求返回明确错误而不是硬跑。

### P1 · 管理面补全

6. **调用方审计**：我的助手被谁调过（哪个节点、多少次、最近一次、成败）。目前只有次数，没有来源明细。
7. **节点级"暂停"**：一键停掉某个节点的所有远端助手（应急用），比逐个停用快。
8. **节点改名**：`POST /api/studio/name` 已有接口，页面上没有入口。
9. **指纹自动同步**：`fingerprint` 已经存了，但没有用作"变了才同步"的判据，现在全靠手动点「同步」或进页面。
10. **studio_id 导出/导入**：换机即新身份（已拍板接受），但要能显式继承，否则对端关系全部作废。
11. **对端删除助手后的本地善后**：现在只 `enabled=False`，影子 agent 与工具行仍在；应有"远端已移除"的明确状态，助手执行时给可读原因。
