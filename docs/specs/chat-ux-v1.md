# 对话页需求拆解（前端 / UX 视角）

定位：这是**使用者的工作台**，不是调试台。同一份 Session/Run 数据，调试台看事件流，这里只看"我问了什么、它做了什么、结果能不能用"。任何为了让开发者方便而暴露的概念，都不该出现在这一页。

## 一、现状盘点（带证据）

1. **单文件 5568 行**（`ChatConsole.tsx`），会话列表、消息流、输入坞、HITL、子代理、执行详情全在一个组件里。任何一处改动都要在 5 千行里定位，行为耦合已经到"改 A 影响 B"的地步。
2. **项目路径卡骑在会话列表头上**（`:4289`）：导航区里放着运行上下文，且与 Agent 配置页的「工作目录」是两份口径。
3. **列表与消息争空间**：桌面固定侧栏 + 窄屏抽屉，抽屉每切换一次会话要开合两次。
4. **工具过程与结果混排**：工具调用、子代理、产物、思考都塞在同一条纵向流里，长的比正文还长。
5. **HITL 打断点不显眼**：等待人工确认时，提示条与普通消息同权重，容易滚过去。
6. **滚动跟随策略不明确**：流式追加时用户往上翻会被拽回底部（或反过来不跟随），两种抱怨都出现过。
7. **长回答不折叠**：一份 3000 字回答把后面的消息全推走，回看要滚很久。
8. **失败态只有一行红字**：没有"重试这一步""换个模型再试"的就地动作。
9. **移动端输入坞偏高**：键盘弹起后可视消息区被压到不足半屏。
10. **调试概念泄漏**：run_id、trace、事件类型在正文里出现（应只出现在"执行详情"里）。

## 二、三个核心任务（其余都是修饰）

- T1 问一句，拿到能用的答案（含流式反馈、可中断、可续写）
- T2 看它到底做了什么（工具调用一行摘要、可展开看参数与结果、产物可预览下载）
- T3 接着上次继续（历史会话一屏可见、能改名/置顶/删除、能回到某一轮重来）

验收时只问三件事：T1 能否 ≤2 次交互完成；T2 能否一眼判断"它查了哪儿、改了什么"；T3 能否在 3 秒内找回上周那次对话。

## 三、信息架构

```
桌面
┌ 侧栏（可折叠，240px）──┬ 主列 ────────────────────────────┐
│ 新建对话              │ 顶栏：助手 · 会话名 · 更多          │
│ 今天 / 昨天 / 更早     │ 消息流（虚拟滚动）                  │
│ · 会话（悬停动作）     │ …                                  │
│                       ├ 输入坞（固定）：附件 @技能 /命令 发送 │
└───────────────────────┴────────────────────────────────────┘
移动
单列：顶栏（菜单 + 助手 + 配置）→ 消息流 → 输入坞；侧栏为左侧抽屉
```

- 侧栏只在宽 ≥1024px 常驻；窄屏收成抽屉，**切换会话后自动关闭**。
- 运行上下文（项目目录/技能数）不放在列表顶部：收进顶栏「···」与 Agent 配置页，二者同源。
- 搜索：顶栏一个入口，搜"我说的句子"和"它答的句子"，结果就地高亮跳转（不做新页）。

## 四、消息流的四个消息类型（每类一条规格）

1. **用户消息**：右对齐浅底；悬停/长按出「复制 / 编辑重发 / 从这里重来」；编辑重发 = 该轮之后全部重算并明确提示。
2. **助手正文**：左对齐无气泡（只有一层浅底卡片）；Markdown 完整渲染；**超过 600 字折叠为 8 行 + 「展开全文」**；末尾一排动作：复制、重试、继续、选更好的回答。
3. **工具调用**：折叠成**一行**——`▸ 检索知识库 · 3 条 · 12ms`；点开才是参数与结果（JSON 用等宽、长串截断 300 字 + 展开）。同一轮连续工具调用合并成一个组（`▸ 4 个动作 · 31s`），默认收起。
4. **子代理 / 编排**：一条时间线块，左侧色条区分 worker；子代理内部过程折叠到二级；「汇入」关系用一句话说明（谁把结果交给谁）。

HITL（等人确认）：**不是消息**，是输入坞上方的固定条（红色强调 + 选项按钮），直到处理完不消失；手机端同样固定在输入坞上方。

## 五、输入坞规格

- 一行文字 + 右侧两个按钮：发送（实心）与停止（运行中替换发送）。
- 左侧：附件（图片/文件）、`@` 技能、`/` 命令；三者都走下拉，不弹窗。
- 上方常驻一条**上下文 chip 行**（可折叠）：项目目录 / 技能数 / 模型；点开即改，改完原地下沉为 chip。
- 高度：单行 52px 起，最多长到 30% 视口后内部滚动；键盘弹起时输入坞贴键盘、消息区自动让位（不用 100vh 硬顶）。
- 发送后不清空草稿区而是**立即上屏为用户消息**（乐观渲染），失败回滚并把原文放回输入框（不丢字）。

## 六、滚动与流式

- 距底 < 80px → 自动跟随；一旦用户上滚超过 80px → 停止跟随并显示「↓ 新消息」浮标，点击回到底部。
- 流式追加时**不改变已渲染内容的高度基准**（避免整页跳动）：思考块固定高度上限，超出内部滚动。
- 切换会话保留各自滚动位置（sessionStorage 记 offset）。

## 七、状态与空态（每条都要有）

无会话、首次进入、运行中、流中断（显示「连接中断，已保留已生成内容」+ 重试）、HITL 等待、额度/模型不可用、工具被拒（权限）、附件超限。空态文案一句人话 + 一个动作，不放插画。

## 八、验收指标（可测量）

| 指标 | 目标 |
|---|---|
| 首屏可交互 | ≤1.5s（本地静态） |
| 消息可视高度 | ≥65% 视口（桌面 900 高） |
| T1 完成交互次数 | ≤2（输入 + 发送） |
| 流式跟随误差 | ≤1 行；上滚后不抢滚动 |
| 工具调用默认占用高度 | ≤1 行/次，成组后 ≤1 行 |
| 长回答折叠 | 600 字触发，展开 1 次点击 |
| 移动端 390×844 | 横向溢出 0；输入坞 + 顶栏总高 ≤ 128px |
| HITL 可见率 | 100%（出现即在视口内） |

## 九、里程碑

- **M1 拆分组件**（1 天）：把 5568 行按「侧栏 / 顶栏 / 消息流 / 消息项 / 输入坞 / 执行详情」拆成 6 个文件，行为不变，tsc 零输出。
- **M2 消息类型规格**（1 天）：四类消息重做（折叠、一行工具、时间线组、HITL 固定条）。
- **M3 输入坞与上下文**（1 天）：chip 行、@ / 命令、附件、乐观发送与失败回滚。
- **M4 滚动与流式**（半天）：跟随阈值、新消息浮标、会话滚动位置记忆。
- **M5 移动端**（半天）：抽屉切换后自动关、输入坞贴键盘、尺寸断言。

## 十、禁止事项

- 不得把项目路径/run_id/事件类型等运行细节放回列表与正文（只出现在执行详情）。
- 不得新增页面或弹窗承载消息动作（复制、重试、编辑都在消息原位）。
- 不得用 hover 作为唯一入口（触屏视为不存在），每个动作至少一个常驻入口。
- 不得为了"简洁"隐藏工具调用（可以折叠成一行，但不能消失）。
- 不得在流式过程中改已渲染内容的宽度/字号（会整页抖）。
- 不得让切换会话丢草稿：切走时把输入框内容存进该会话的草稿位。
