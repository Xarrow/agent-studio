# 知识工作台：一页跑完「上传 → 向量化 → 标签 → 技能 → 召回 → 图谱」

目标：用户从"我有份文档"到"助手查得到它"，全程不离开一个页面；文档更新后同一条流水线自动重跑；图谱可点、可筛、可跳转。

## 一、现状缺口（先对齐事实）

已有：上传（多文件）、链接抓取、解析分块、本地/HTTP 向量化、`document_tag`（模型候选 + 用户自定义）、标签级 Skill 草稿与发布、`query_map` 检索扩词、召回面板（文档自召回 / 标签召回 / 助手命中 / 页面搜索）、图谱接口（分类→文档→标签→技能→助手）。

缺的五块，正好对应这次需求：

1. **不能粘贴**：只能传文件或给 URL，贴一段文本没入口。
2. **向量化后不出标签**：标签要么靠「整理」跑 LLM，要么手打。用户点完 embedding 应该马上看到关键词。
3. **一键生成 Skill 要绕**：得先去标签页找到标签再点生成；文档页没有入口。
4. **召回只能整体抽样**：面板给的是全局自召回率，用户无法"用我刚想到的问法试一下"。
5. **图谱是死的**：手写 SVG 只能看，点不动；更新文档后也没有"这条线的下游要重算"的提示。

## 二、页面结构（一屏四段，不跳页）

```
┌ 顶部工具条 ────────────────────────────────────────────┐
│ [上传文件] [粘贴文本] [搜索框……………………]  共 N 份 · M 待办 │
└───────────────────────────────────────────────────────┘
┌ 文档流水线（列表，一行一份）─────────────────────────────┐
│ ✓上传 ✓解析 ✓向量化 ·标签 ·技能   名称   分类   [下一步按钮] │
│ 点行 → 就地展开：标签编辑 / 技能预览 / 召回试打 / 版本    │
└───────────────────────────────────────────────────────┘
┌ 选中项：标签与技能（随上面选中的文档变化，不新开页）───────┐
│ 关键词：[付款期限][验收][违约金] + 添加…   ← 模型建议可一键全收 │
│ 技能：由这些标签生成 → [生成] → 预览 SKILL.md → [发布]     │
└───────────────────────────────────────────────────────┘
┌ 召回与图谱（同一屏，可折叠）─────────────────────────────┐
│ 试打输入 → 命中/未命中 + 命中路径 + 延迟   [跑一遍全库基线] │
│ 图谱：分类 → 文档 → 标签 → 技能 → 助手（可点选高亮、点节点筛）│
└───────────────────────────────────────────────────────┘
```

## 三、用户路径与点击数（验收口径）

| 动作 | 现在 | 目标 |
|---|---|---|
| 上传一份文档到"可检索" | 上传 → 切段 → 点向量化（≈4） | 上传 → 行内「向量化」（2） |
| 看到关键词并确认 | 切到分类段 → 等整理 → 采纳（≈5） | 向量化完成后自动出，行内一键全收（1） |
| 由标签生成技能 | 切标签段 → 找标签 → 生成 → 切回看草稿（≈5） | 选中文档 →「生成技能」→ 预览发布（2） |
| 用一句话试召回 | 无入口 | 试打框输入即看结果（1） |
| 文档更新后重跑 | 重新上传 + 手动逐步做 | 更新版本 → 自动排队重跑三件事（0） |

## 四、后端改动清单（端点级）

1. `POST /api/knowledge/documents/paste`
   入参 `{title, text, category?, tags?[]}`；落成 md 文档（`source=paste`），走同一条解析→分块流程。文本 <20 字直接 422（避免垃圾条目）。
2. `POST /api/knowledge/documents/{id}/keywords`
   关键词生成，**优先用向量**：对每块用「块向量与全库质心的偏离度 + 块内高频词」打分，取 5–8 个；命中不足再退 LLM。产出写 `document_tag(status=candidate, source=model, confidence)`。语义：这一步不该花 30 秒，目标 <2s（本地模型）。
3. `POST /api/knowledge/documents/{id}/skill`
   按该文档已采纳标签生成 Skill 草稿（等价于现在的 `POST /skill-drafts {doc_ids}` + 自动带 tag_ids），返回草稿 id。
4. `POST /api/knowledge/recall/probe`
   入参 `{query, limit?}`；调 `hybrid_search`，返回 `{hits:[{doc, snippet, score, matched_path}], latency_ms, query_map_applied[]}`。前端用它做"试一下"。
5. `POST /api/knowledge/documents/{id}/versions` 扩展
   新版本解析完成后自动触发：`embed` → `keywords` → 把来源含该文档的 Skill 标 stale（已有 `source_fp`，复用）。失败只记 `pipeline_error` 不影响文档可用。
6. `GET /api/knowledge/graph` 扩展
   节点带 `degree`（连接数）与 `doc_ids`（聚合节点用它下钻）；边带 `kind`（已有）。前端点击时用它做筛选与高亮，不需要新端点。

## 五、前端改动（一个页面）

- 顶部工具条：加「粘贴文本」弹层（标题 + 正文 + 可选标签），提交后立刻出现在流水线列表首行。
- 流水线行：五个勾选点（复用现有 PipelineSection），`next` 按钮按状态给「向量化 / 出关键词 / 生成技能」。点行展开的详情里加三块：标签编辑（候选一键收、自定义回车加）、技能预览（草稿正文 + 发布）、召回试打（输入框 + top5 结果 + 命中路径）。
- 召回与图谱：把现有 `RecallSection` 和 `KnowledgeGraph` 收进同一个折叠段；图谱改成可点——点标签高亮其文档与技能、点技能显示挂载的助手、点文档展开详情。
- 不新增页面路由；所有动作使用现有的 `api.ts` 封装，新增四个方法即可。

## 六、里程碑与验收

**M1 粘贴 + 行内向量化（半天）**
验收：贴 300 字文本 → 列表首行出现 → 点向量化 → 2 秒内 `embed_status=ready`；手机上不跳页完成。

**M2 关键词自动产（1 天）**
验收：向量化完成后 2 秒内出现 3~8 个候选标签；与人工标注对比，前 5 个里至少 3 个reasonable（用现有 4 份文档做基线）；用户点「全部采纳」后 `doc.tags` 同步。

**M3 一键技能（半天）**
验收：选中一份文档点「生成技能」→ 30 秒内出草稿 → 预览可见「适用问题 / 查询词映射」→ 发布后 `query_map` 生效（用「账期多久」验证：发布前查不到、发布后命中）。

**M4 试打召回 + 图谱交互（1 天）**
验收：试打框输入「账期多久」→ 返回命中文档 + `matched_path` + 延迟 <300ms；图谱点标签节点 → 该标签下文档与技能高亮，点技能 → 显示挂载助手；手机 390×844 无横向溢出、点击区 ≥36px。

**M5 更新重跑（半天）**
验收：给已上线的文档传新版本 → 自动排队 embed+keywords；完成后 Skill 行显示「来源已变化」；旧版本仍可下载。

## 七、风险与回退

| 风险 | 处置 |
|---|---|
| 关键词质量差（纯统计抽词在同义词上不稳） | 先统计 + 已有标签词表做归一，不达标再退 LLM；不达标就在验收里如实写"未达标清单" |
| 自动重跑把机器拖慢（本地模型 375MB 峰值） | 单并发队列（`asyncio.Semaphore(1)`），串行跑，失败重试 1 次 |
| 图谱节点过多看不懂 | 默认只显示与选中项相连的两跳；「显示全部」需手动点 |
| 一页塞太多又变复杂 | 四段都可折叠，默认展开「流水线」，其余折叠但显示摘要数字 |

## 八、禁止事项

- 不得把「粘贴」做成只能纯文本：md 语法要保住（标题、列表），否则分块质量掉。
- 不得在向量化未完成时允许生成技能（来源正文不全，生成的映射会缺）。
- 不得自动发布 Skill：必须人点发布。
- 不得把「自动重跑」做成同步阻塞请求：走后台任务，失败不影响文档本身可用。
- 不得新增页面路由（这条需求的验收标准就是"不跳页"）。
