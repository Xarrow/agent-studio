# 知识中心交互重构方案（激进版）

立场：现有页面在"功能正确"上已经合格，但在"操作是否自然"上不及格。根因不是样式，是**同一批对象被切成四个互不相干的区域**：文档在「流水线」和「文档列表」各出现一次，标签在「分类与标签」段，技能草稿在另一个入口，召回与图谱又被塞进标签段。用户每做一步都要先回答"我现在在哪一段"。

本方案的前提是：**不迁就现有交互**。允许删段、合并入口、改层级。

## 一、现状的五个硬伤（都能量化）

| 硬伤 | 证据 |
|---|---|
| 同一批文档在一屏出现两次 | 「入库流水线」一块 + 「文档列表」一块，各自带状态与按钮 |
| 一条流程被切成三段 | 向量化在文档段、标签在标签段、技能在标签行/详情里 |
| 「待确认」分散三处 | 整理草稿（文档段顶部）、模型标签候选（详情内）、技能草稿（标签行） |
| 召回与图谱藏在「分类与标签」里 | 它是验证工具，不是标签对象 |
| 文档生命周期藏在「设置」里 | 存储位置、回收站跟文档强相关，却离文档两段远 |

## 二、新信息架构：三块，一屏

```
┌─ 投放区（占一行的输入）──────────────────────────────────┐
│ 拖文件到这里 · 或粘贴文本 · 或贴链接        [选择文件]      │
└─────────────────────────────────────────────────────────┘
┌─ 文档带（左，主列表）───┐┌─ 工作区（右，随选中切换）──────┐
│ ○ 差旅报销规范  ✓✓✓·   ││ 差旅报销规范.md   v2 · 已就绪   │
│ ○ 采购合同      ✓✓··   ││ ① 标签  [报销][出差]+ 3个候选  │
│ ○ kdoc.md      ✓✓✓✓   ││ ② 技能  待生成 → [生成]        │
│ [筛选：全部/未完成]     ││ ③ 试打  [问点什么…] [查]       │
└────────────────────────┘│ ④ 版本  v2 / v1  ·  移到回收站  │
                          └────────────────────────────────┘
┌─ 体检区（折叠，默认只露三个数字）──────────────────────────┐
│ 文档自召回 100% · 标签召回 100% · 助手覆盖 1/10   [展开]     │
│ 展开后：试打历史 + 图谱（点节点 = 筛选左边的文档带）        │
└─────────────────────────────────────────────────────────┘
```

- 桌面：文档带 / 工作区两栏（≥1024px 各占 42% / 58%）；手机：文档带在上，选中后工作区以**页面内下一屏**展开（不是浮层、不是弹窗）。
- 「分类与标签」「设置」两个段取消：分类变成文档带顶部的筛选器；存储与回收站进工作区第 ④ 区。
- 「入库流水线」不再是独立列表，它就是文档带的每一行（勾点即状态）。


## 二·修订：整个流程装在**一个组件**里（取代两栏方案）

上一版提的"左列表 + 右工作区"仍然把对象和它的操作用一条边界隔开了：选中在左、操作在右，
用户的视线要在两处来回。修订为**卡片即流程**——一份文档就是一个组件，它自己的四步都在它内部完成。

```
┌─ 投放卡（永远排第一张，同一种组件形态）──────────────────────┐
│ 拖文件 · 粘文本 · 贴链接                     [选择文件]        │
└───────────────────────────────────────────────────────────┘
┌─ 文档卡（折叠态：一行）────────────────────────────────────┐
│ ▸ 差旅报销规范.md   ① ✓  ② ✓  ③ ·   ④ ·        [向量化]     │
└───────────────────────────────────────────────────────────┘
┌─ 文档卡（展开态：同一张卡内部往下长）──────────────────────┐
│ ▾ 差旅报销规范.md   v2 · 已就绪 · 4 块 · 512 维             │
│                                                             │
│   ① 标签   [报销][出差] ×   + 3 个候选  [全部接受]  [添加…]  │
│   ② 技能   由这些标签生成 →  [生成]   草稿：采购条款速查…    │
│   ③ 试打   [问点什么…            ] [查]   命中 3 条 · 12ms   │
│   ④ 版本   v2 · v1   |   原件下载    |   移到回收站           │
└───────────────────────────────────────────────────────────┘
```

规矩：

1. **卡内推进**：①→④ 是这张卡自己的四个格子，动作都写在格子里，不出现"去另一边看"。
2. **折叠态必须极简**：一行＝名称 + 四个状态点 + 一个主动作。一屏至少 8 张，否则卡片流会把列表变成滚动地狱。
3. **一次只展开一张**（手风琴）：展开的那张不影响别的卡的折叠高度，避免长列表跳动。
4. **投放卡与文档卡同一形态**：没有"先打开上传弹窗"这一步——流程的第一格就是把它拖进来。
5. **状态点在卡内可点**：点 ② 的技能点直接跳到技能格并展开，不用先展开再滚动。
6. **图谱/体检不塞进卡片**：它们不属于单份文档的流程，留在页面底部的体检区（点节点→过滤卡片流）。

为什么推翻两栏：卡片流的代价是密度下降、好处是**没有跨区跳转**；为了把密度补回来，
折叠态只保留"名称 + 四点 + 一个按钮"，其余全部收进展开态——这也符合"一次只做一件事"。

## 三、五条交互原则（每条都能验收）

1. **一个投放口**：文件、文本、URL 共用一个输入框，自动识别类型；用户不需要先决定"我这是哪种"。
2. **一个主动作**：每行右侧只有一个按钮，文案随状态变（向量化 → 出关键词 → 生成技能 → 已完成）。没有第二排按钮，不进「⋯」。
3. **选中即工作区**：所有对对象的操作都在右侧发生，列表只负责找与选；连续处理多份文档时不需要滚动找详情（旧的"行内展开"会把列表推走）。
4. **待确认只剩一处**：模型标签候选、技能草稿、来源变化提示全部进工作区第 ①②区，且各自带一键处理（全部接受 / 生成 / 重新生成）。
5. **图谱是筛选器不是装饰**：点标签节点 → 左边文档带只剩该标签下的；点技能 → 显示挂了它的助手；点文档 → 选中该行。图谱不再是死图。

## 四、状态机（每份文档）

```
上传/粘贴 ──解析中──▶ 已就绪 ──[向量化]──▶ 已向量 ──[出关键词]──▶ 已打标
                              ▲                                  │
                              │                                  ▼
                       版本更新/自动重跑                  [生成技能] ──▶ 已完成
                                                        └─ 来源变化 ──▶ 可重新生成
```

- 每步完成瞬间给**下一个动作**（按钮文案即时切换），不再让用户自己判断还剩什么。
- 失败态：行内红字一行原因 + 「重试」，不弹窗。
- 自动重跑（版本更新）时行上显示「重跑中…」小字，不阻塞其它操作。

## 五、要删掉的东西（明确列出，避免"看起来改了"）

- 独立的「入库流水线」区块（与文档列表合并）
- 独立的「分类与标签」段（分类 → 筛选器；标签 → 工作区；图谱 → 体检区）
- 独立的「设置」段（存储 → 工作区 ④；回收站 → 工作区 ④ 的入口）
- 行内展开详情（工作区取代；行点击只负责选中）
- 三处分散的"待确认"（合并进工作区 ①②）

## 六、验收指标

| 指标 | 目标 |
|---|---|
| 从 "文件在手" 到 "可检索" | ≤2 次点击（投放 → 点向量化） |
| 从 "可检索" 到 "生成技能" | ≤2 次点击（选中 → 生成），且全程不离开当前屏 |
| 同一对象在一屏出现次数 | 1 次（卡片内推进，不跨区） |
| 折叠态一屏可见文档数 | ≥8 张（1440×900）/ ≥4 张（390×844） |
| 需要滚动才能看全一条流程 | 桌面不出现；手机 ≤1 次翻页 |
| 图谱点击到"看到相关文档" | 1 次点击 |
| 新增页面/弹窗 | 0 个 |
| 手机 390×844 | 横向溢出 0；主按钮 ≥36px；点击区不重叠 |

## 七、里程碑

- **M1 结构重排（半天）**：删两段、合并两套列表、加工作区两栏骨架；旧功能全部搬位不丢。
- **M2 投放区（半天）**：文件/文本/URL 三合一，自动识别；拖拽整页可放。
- **M3 工作区四区（1 天）**：标签（候选一键收 + 自定义）、技能（生成/预览/发布/来源变化）、试打、版本与回收站。
- **M4 体检区联动（1 天）**：三数字 + 展开试打 + 图谱点选筛选文档带。
- **M5 响应式与打磨（半天）**：手机下工作区变下一屏；键盘可达；空态文案。

## 八、风险与回退

- 两栏在 1024–1280 可能挤：工作区最窄 520px，低于则自动变上下布局（不断点、不裁切）。
- 合并入口后老用户找不到原位置：首版在工作区对应区加一次性指引点（点击即消失，不长期占位）。
- 回退方式：结构用 `layout` 开关（`workspace_v2`）包一层，出问题切回旧三段；数据层零改动，因此回退无迁移成本。

## 九、禁止事项

- 不得新增页面路由或弹窗（"不隔离"的底线）。
- 不得把主操作藏进「⋯」或 hover 才出现的位置。
- 不得为了"简洁"删掉状态可见性（每行必须能看到走到哪一步）。
- 不得让选中态与详情脱节（选中行与其工作区必须同时高亮）。
- 不得在手机上用横向滚动容纳两栏。
